01What you end up with

A Hermes agent is a process with a shell, a scheduler and a set of tools. With this setup it has:

  • 31 skills built from real on-chain work: mint execution, rarity ranking that matches OpenSea rank for rank, reveal sniping, secondary buys, wallet forensics, contract and minter analysis, collection production.
  • A rundown toolkit: rarity engines, a SeaDrop multi-wallet mint tool, a Seaport buy path with a fill diagnostic, wallet P&L reconstruction, keyless volume and minter-legitimacy analysis, and Solidity drop mechanics.
  • Proof-of-work minting that scales: a CUDA kernel verified against a CPU reference, plus a Modal farm that mines Hashcats across N H100 shards and checks every solution before it broadcasts.
  • A scheduler, so a watch job can ping you when a collection reveals while you are asleep.

It runs the same on a laptop and on a server. A server just means it keeps working when you close the lid, which is what you want for anything on a timer.

02Install Hermes

On a VPS, if you want it always on

Ubuntu 22.04 or 24.04, 2 vCPU, 4 GB RAM, 40 GB disk. Two gigabytes is enough for the agent alone. Take four if you also want a browser running.

ssh root@YOUR_SERVER_IP

adduser hermes && usermod -aG sudo hermes
rsync --archive --chown=hermes:hermes ~/.ssh /home/hermes/
ufw allow OpenSSH && ufw enable
loginctl enable-linger hermes     # without this, your bot dies when SSH closes

su - hermes
sudo apt update && sudo apt install -y git curl tmux build-essential python3-venv

On your own machine

Skip to the install. macOS, Linux and WSL2 all work.

The install

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.bashrc
hermes --version
hermes doctor

The installer handles Python, Node, ripgrep, ffmpeg, the clone and the virtual environment. hermes doctor tells you what else it needs.

05GPU proof-of-work minting

This is the part most people ask about, so here is the whole loop.

What the contract is asking for

You get a target and you search for a nonce whose hash lands under it. Two schemes are covered, both single-Keccak-block preimages, which is why a GPU kernel beats a CPU by orders of magnitude:

Hashcats   keccak256( miner(20) ‖ nonce(32) ‖ prev(32) ‖ anchor(32) ) < target
FAB4200    keccak256( chainid(32) ‖ contract(20) ‖ minter(20) ‖ nonce(32) ) < target

Hashcats links each token to the last one through prev and pins the round to a block with anchor, so the token chain is sequential and cannot be parallelized across tokens.

Why a CPU does not work

At 40 bits the expected work is around 1.1e12 hashes per solve. A laptop does tens of millions per second. An H100 does about 7 GH/s. One of those finishes in minutes.

Check the kernel before you rent anything

cd toolkit/pow
./hcminer selfcheck 0x<miner> 0x<prev> 0x<anchor>

That compares the optimised path against an independent reference Keccak over 200,000 nonces. A kernel with an endianness bug mines forever and finds nothing, and you pay for every second of it. The two bugs to know: the nonce has to be byte-swapped before it is XORed into the state word, and the leading-zero test has to run against the digest word in the right byte order. Both are fixed in the shipped source.

The farm

toolkit/pow/hashcats-farm/ is the full loop: verified CUDA kernel, Modal H100 shards, local signing and broadcast.

pip install modal eth-account pycryptodome coincurve
modal setup

modal run hashcats_modal.py --mode probe         # kernel vs CPU reference
modal run hashcats_modal.py --mode bench         # GH/s on an H100
python3 hashcats.py state                        # current round
python3 farm.py --shards 4 --minutes 30 --dry    # verify + simulate, no spend
python3 farm.py --shards 8 --minutes 30 --key ~/.hermes/secrets/hashcats_key

Every candidate is verified against a Python keccak and re-checked against the live round before broadcast, so a stale nonce never costs gas.

Two things that will stop you. A working farm with an unfunded broadcasting wallet produces nothing, so fund the wallet first. And read the round once, then mine: the Robinhood RPC rate-limits per IP on reads and writes, so a shard polling in a loop gets 429s and looks like a protocol failure.
Costs, plainly. A GPU mint is a contest entry, not a button. You pay for compute whether or not you land a token, and other miners race the same round. Do the arithmetic on your own spend, and stop when the round goes stale.

Build it yourself

gcc -O3 -fopenmp -o hcminer hcminer.c
nvcc -O3 -o hcminer_cuda hcminer.cu

Skip -march=native on a cloud build: the build host is not the execution host and the binary dies with SIGILL. On macOS, clang has no OpenMP, so install libomp or build single-threaded with the stub in toolkit/pow/README.md.

06The rest of the toolkit

cd toolkit

# rarity: rank a collection, matching OpenSea's numbers
python3 rarity/rarity_engine.py compute
HELD="12,44,91" python3 rarity/gen_dash.py

# recon before spending anything
python3 analysis/collection_volume.py <contract> 3000000
python3 analysis/minter_legitimacy.py <contract> <deploy_block>
python3 analysis/sweep_scope.py <opensea-slug>

# SeaDrop public mint across many wallets
python3 mint/seadrop_fire.py recon  <collection>
python3 mint/seadrop_fire.py wallet <collection> 3
python3 mint/seadrop_fire.py fire   <collection> --keyfile ~/.hermes/secrets/x_key --quantity 1

# buy from secondary — dry run first, --live spends
python3 sniper/buy_secondary.py <slug> --target-eth 0.001

# wallet P&L: mints separated from buys, gas counted
python3 wallets/wallet_recon.py <address>

Every spending path simulates with eth_call first and needs an explicit flag to broadcast. That is deliberate, and it is what stops a batch of reverts.

For launches like SpawnHood, the useful skills are nft-mint-recon for working out what the mint actually is, ethereum-data-pipelines for reverse-engineering an unknown mint site, and rh-chain-rarity-sniping for getting rare ones at the floor after a reveal.

07Connect Discord

Worth doing if you want to talk to the agent from your phone instead of a terminal.

  1. discord.com/developers/applications → New Application. The bot reads message text, so it needs Message Content Intent under the Bot tab or it will look completely dead. Reset the token and copy it.
  2. Invite it with scopes bot and applications.commands, and permissions 274878286912:
https://discord.com/oauth2/authorize?client_id=YOUR_APP_ID&scope=bot+applications.commands&permissions=274878286912
  1. Copy your user ID: Settings → Advanced → Developer Mode, then right-click your name → Copy User ID.
  2. Configure and run:
hermes gateway setup        # choose Discord, paste token + user ID
hermes gateway run          # foreground test first
hermes gateway install      # then as a service
hermes gateway start

Without DISCORD_ALLOWED_USERS the gateway denies everyone. In server channels the bot answers only when mentioned, unless you add the channel to DISCORD_FREE_RESPONSE_CHANNELS.
